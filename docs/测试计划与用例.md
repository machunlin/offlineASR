# 自动化测试与现场验收用例

## 1. 自动化测试原则

保持现有 Maven + JUnit 5 + Node.js 测试方式，不引入额外测试框架。自动化测试分为三层：

1. Java 单元/集成测试：`mvn clean test`。
2. 浏览器前端行为合同：`node scripts/verify-js-contract.mjs`。
3. Windows x64 构建与静态校验：GitHub Actions Windows runner 执行 `mvn -Pwindows-x64 clean test package`，并检查 PowerShell 语法和最终 JAR 内的 native library。

任何自动化测试均不能模拟真实 Chrome 麦克风和客户 Windows 主机上的 JNI 运行时，相关项目必须现场执行并记录。

## 2. 自动化用例

| 编号 | 层级 | 场景 | 预期结果 |
|---|---|---|---|
| J-01 | Java | 模型文件缺失 | 应用健康状态 NOT_READY，不误报 READY |
| J-02 | Java | 上传文件为空 | 返回 INVALID_REQUEST |
| J-03 | Java | 上传文件超过配置上限 | 返回 FILE_TOO_LARGE |
| J-04 | Java | FFmpeg 不存在 | 返回 SERVICE_NOT_READY |
| J-05 | Java | FFmpeg 超时 | 进程被强制终止，返回 PROCESSING_TIMEOUT |
| J-06 | Java | FFmpeg 输出 PCM 超过 61 秒上限 | 在读取 PCM 到内存前拒绝 |
| J-07 | Java | PCM 样本数不是 Float32 对齐长度 | 返回 AUDIO_DECODE_FAILED |
| J-08 | Java | 解码音频时长超过 60 秒 | 返回 AUDIO_DURATION_EXCEEDED |
| J-09 | Java | 临时目录路径越界 | 拒绝删除 |
| J-10 | Java | 两个请求复用相同 requestId | 创建不同临时目录，互不覆盖 |
| J-11 | Java | JNI 原生库加载失败 | 记录完整服务端异常，health 不返回 READY |
| JS-01 | Node | ASR API 成功 | Promise、回调、事件只派发一次 |
| JS-02 | Node | API 返回非 JSON 错误 | Promise reject，包含稳定错误码和消息 |
| JS-03 | Node | file:// 打开页面 | 提示必须从 localhost 服务访问 |
| JS-04 | Node | 录音达到 60 秒 | 自动停止录音并提交识别 |
| JS-05 | Node | 识别成功 | “开始录音”按钮恢复，可再次录音 |
| WIN-01 | Windows CI | Windows x64 Maven 构建 | 测试及打包成功 |
| WIN-02 | Windows CI | JAR native library | 仅包含 Windows x64，不包含 macOS ARM64 |
| WIN-03 | Windows CI | PowerShell 脚本语法 | 无解析错误 |

## 3. 现场测试物料

不将客户录音、个人语音或未经授权的语音样本提交到代码仓库。测试人员使用以下固定口令录制 5–10 秒测试音频，现场记录预期文本和实际文本：

- 物料 A：`今天上午九点开始开会，下午五点结束。`
- 物料 B：`请把第一批物料送到二号仓库，数量是三百件。`
- 物料 C：`订单编号 A B C 一二三，预计明天上午交付。`

每次测试记录：Windows 版本、CPU 型号、内存、Java 版本、Chrome 版本、麦克风设备、模型 SHA-256、录音时长、识别文本、解码耗时、推理耗时。

## 4. Windows 现场验收用例

| 编号 | 操作 | 通过标准 |
|---|---|---|
| F-01 | 执行 windows-verify-package.ps1 | 文件、Java、FFmpeg、哈希校验通过 |
| F-02 | 启动应用并访问 health | HTTP 200，applicationStatus=READY |
| F-03 | Chrome 首次允许麦克风 | 浏览器成功录音并返回文本 |
| F-04 | 连续录音三次 | 每次均可开始、停止和识别 |
| F-05 | 录音 60 秒 | 倒计时归零，自动停止并识别 |
| F-06 | 发送超过 60 秒的音频 | 服务端拒绝，不产生超限 PCM 内存分配 |
| F-07 | 禁用互联网后重启 | 模型、FFmpeg、JNI 正常，仍可识别 |
| F-08 | 观察日志滚动 | 每日归档，超过 15 天的归档清理 |
| F-09 | 运行服务启停 | 服务启动、停止、重启正常 |
| F-10 | 非本机访问 8080 | 默认配置下连接失败 |

## 5. 执行命令

macOS/开发机：

```bash
mvn clean test package
node scripts/verify-js-contract.mjs
```

Windows x64：

```powershell
mvn -Pwindows-x64 clean test package
powershell -ExecutionPolicy Bypass -File .\\scripts\\windows-verify-package.ps1
node .\\scripts\\verify-js-contract.mjs
```

Windows 部署包必须在发布机生成 SHA-256 清单；客户现场只执行校验，不应重新生成可信清单。
