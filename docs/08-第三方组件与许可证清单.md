## 3. sherpa-onnx Native Runtime

`sherpa-onnx-jvm-2.0.3.jar` 只是 Java API/Wrapper，会被 OfflineASR 打入 Fat JAR；它不包含 JNI 或 ONNX Runtime Native。客户只需额外下载对应平台的一个官方 Native JAR。该 Native JAR 同时包含 `sherpa-onnx-jni` 和 `onnxruntime` 原生库，解压后即可使用，**不需要再单独下载 ONNX Runtime**。

### 3.1 已核验直接下载地址

| 平台 | 文件 | SHA-256 |
|---|---|---|
| Windows x64 | `sherpa-onnx-native-lib-win-x64-2.0.3.jar`，https://github.com/k2-fsa/sherpa-onnx/releases/download/v2.0.3/sherpa-onnx-native-lib-win-x64-2.0.3.jar | `26a9072f4a47be3a73bfbbba5f25e6e8b84b24734be651de2d480ae753ae6508` |
| Linux x64 | `sherpa-onnx-native-lib-linux-x64-2.0.3.jar`，https://github.com/k2-fsa/sherpa-onnx/releases/download/v2.0.3/sherpa-onnx-native-lib-linux-x64-2.0.3.jar | `42330fbcfe4f771386545397ebf8a8dd2176ff913a254331226c01ad87982e17` |
| macOS ARM64 | `sherpa-onnx-native-lib-osx-aarch64-2.0.3.jar`，https://github.com/k2-fsa/sherpa-onnx/releases/download/v2.0.3/sherpa-onnx-native-lib-osx-aarch64-2.0.3.jar | `9c85930bcf081eb285a324f0f97eec63054a2a6ba7baf47408b83683add2a675` |

### 3.2 安装位置与加载方式

1. 下载对应平台的 Native JAR 并校验 SHA-256。
2. 将两个库**扁平解压**到部署目录下的 `external/sherpa-onnx-native/`，例如：
   - Windows：`C:\offline-asr\external\sherpa-onnx-native`
   - Linux：`/opt/offline-asr/external/sherpa-onnx-native`
   - macOS：`<项目>/external/sherpa-onnx-native`
   - Native JAR 内部路径是 `sherpa-onnx/native/<platform>/...`；不能把该子目录原样保留，否则 `LibraryUtils` 找不到库。
3. Linux/macOS 解压示例（按平台选择文件名）：
   ~~~bash
   mkdir -p external/sherpa-onnx-native
   unzip -j sherpa-onnx-native-lib-linux-x64-2.0.3.jar \
     'sherpa-onnx/native/linux-x64/*' -d external/sherpa-onnx-native
   ~~~
4. Windows 解压示例：
   ~~~powershell
   New-Item -ItemType Directory -Force external\sherpa-onnx-native | Out-Null
   tar -xf sherpa-onnx-native-lib-win-x64-2.0.3.jar `
     -C external\sherpa-onnx-native --strip-components=3 `
     sherpa-onnx/native/win-x64/onnxruntime.dll `
     sherpa-onnx/native/win-x64/sherpa-onnx-jni.dll
   ~~~
5. 解压后目录必须同时包含：
   - Windows：`onnxruntime.dll`、`sherpa-onnx-jni.dll`
   - Linux：`libonnxruntime.so`、`libsherpa-onnx-jni.so`
   - macOS：`libonnxruntime.dylib`、`libsherpa-onnx-jni.dylib`
6. 启动脚本会自动把该目录传给应用；应用在 sherpa-onnx 类首次加载前将 `ASR_SHERPA_NATIVE_PATH` 映射为系统属性 `sherpa_onnx.native.path`。
7. 验证命令示例：
   - Windows：`Get-ChildItem external\sherpa-onnx-native`
   - Linux/macOS：`find external/sherpa-onnx-native -maxdepth 1 -type f`
8. 服务健康检查必须返回 `modelLoaded=true`。如失败，先核对平台和 CPU 架构，再确认两个 Native 文件同时存在于目录根层。

### 3.3 常见故障

- `UnsatisfiedLinkError` 或健康检查 `modelError` 包含 Native Runtime：通常是 `ASR_SHERPA_NATIVE_PATH` 未设置、目录不存在、两个文件缺一，或平台不匹配。
- Windows 部署还需确认 Microsoft Visual C++ Redistributable x64 已安装；项目不随包分发该运行库。
- 不要把 macOS Native 文件用于 Windows/Linux，也不要混用 ARM64 与 x64。

### 4.1 下载与校验

- 归档名：`sherpa-onnx-sense-voice-zh-en-ja-ko-yue-int8-2025-09-09.tar.bz2`
- 下载地址：https://github.com/k2-fsa/sherpa-onnx/releases/download/asr-models/sherpa-onnx-sense-voice-zh-en-ja-ko-yue-int8-2025-09-09.tar.bz2
- SHA-256：`7305f7905bfcf77fa0b39388a313f3da35c68d971661a65475b56fb2162c8e63`
- 文件大小：165,783,878 字节
- 必需文件：解压目录下的 `model.int8.onnx` 和 `tokens.txt`
- 模型包 README 实际指向 `https://huggingface.co/ASLP-lab/WSYue-ASR/tree/main/sensevoice_small_yue`；原始 SenseVoiceSmall 许可依据与该上游模型卡许可仍需许可方确认。

### 4.2 安装位置

- Windows：`C:\offline-asr\models\SenseVoiceSmall`
- Linux：`/opt/offline-asr/models/SenseVoiceSmall`
- macOS：`<项目>/models/SenseVoiceSmall`
- 可通过 `ASR_MODEL_DIR` 指定其他绝对路径。

### 4.3 验证与故障排查

1. 校验归档 SHA-256。
2. 解压时去掉模型包顶层目录，确保上述位置直接包含两个必需文件：
   ~~~bash
   mkdir -p models/SenseVoiceSmall
   tar -xjf sherpa-onnx-sense-voice-zh-en-ja-ko-yue-int8-2025-09-09.tar.bz2 \
     -C models/SenseVoiceSmall --strip-components=1
   ~~~
3. 验证命令：
   - Windows：`Get-FileHash models\SenseVoiceSmall\model.int8.onnx -Algorithm SHA256`
   - Linux/macOS：`shasum -a 256 models/SenseVoiceSmall/model.int8.onnx`
4. 健康检查返回 `modelLoaded=true` 表示模型已加载。
5. 如提示缺少模型，检查 `ASR_MODEL_DIR`、必需文件名和文件是否完整；不要改模型文件名。

同 Release 的 `checksums.sha256`：https://github.com/FFmpeg-Builds/FFmpeg-Builds/releases/tag/autobuild-2026-11-26-12-56 。macOS 使用 FFmpeg 官方源码 `9.0.2`，不依赖 Homebrew 当前滚动版本。

### 5.2 安装与验证

#### Windows x64

解压后将 `bin\\ffmpeg.exe` 加入 `PATH`，或设置 `ASR_FFMPEG` 为其绝对路径。

#### Linux x64

解压后将包含 `ffmpeg` 的 `bin` 目录加入 `PATH`，或设置 `ASR_FFMPEG` 为其绝对路径。

#### macOS ARM64：从固定源码构建

前置条件：安装 Xcode Command Line Tools（`xcode-select --install`），并具备 `clang`、`make`、`xz`。以下构建关闭网络访问和外部库自动探测，不启用 GPL/nonfree 选项，减少对本机 Homebrew 依赖的影响；实际构建产物仍应按 FFmpeg 的许可证和配置结果复核。

```bash
curl -fL https://ffmpeg.org/releases/ffmpeg-9.0.2.tar.xz -o ffmpeg-9.0.2.tar.xz
printf '%s  %s\\n' '8c3850283eb25fa026482078a04051e0be17347b09ef81a0849bec15a96e002e' 'ffmpeg-9.0.2.tar.xz' | shasum -a 256 -c -
tar -xJf ffmpeg-9.0.2.tar.xz
cd ffmpeg-9.0.2
./configure \\
  --prefix="$HOME/opt/ffmpeg-9.0.2" \\
  --disable-debug \\
  --disable-doc \\
  --disable-ffplay \\
  --disable-network \\
  --disable-autodetect \\
  --disable-shared \\
  --enable-static \\
  --enable-ffmpeg
make -j"$(sysctl -n hw.ncpu)"
make install
```

配置并验证：

```bash
export ASR_FFMPEG="$HOME/opt/ffmpeg-9.0.2/bin/ffmpeg"
"$ASR_FFMPEG" -version
```

将 `ASR_FFMPEG` 写入运行 OfflineASR 的 shell 环境。源码地址为 FFmpeg 官方发布目录；版本说明见 [FFmpeg 9.0.2](https://www.ffmpeg.org/download.html)。上述 SHA-256 值来自第三方 Fossies 对同一归档的公布值，并非 FFmpeg 官方发布页提供的校验值；对供应链签名有强制要求的客户，应另外下载并验证官方 `.asc` detached signature。

#### 通用验证

执行 `ffmpeg -version` 或 `"$ASR_FFMPEG" -version`。成功判定：命令退出码为 0 且输出版本信息；macOS 构建应显示 `ffmpeg version 9.0.2`。失败时检查 `PATH`、`ASR_FFMPEG` 绝对路径、执行权限和目标架构。

### 5.3 许可与风险

FFmpeg-Builds 是第三方构建项目，不是 FFmpeg 官方预编译二进制。本清单只列 LGPL-only 构建入口。客户选择其他构建时必须重新核验是否启用 GPL/nonfree 组件，并自行确认源码、修改补丁和 LGPL 再分发义务。

## 6. 应用包边界

应用包只包含：

- `app/offline-asr.jar`
- `config/application.yml`
- 启动、状态、安装、卸载和校验脚本
- 项目 `LICENSE`、`THIRD_PARTY_NOTICES.md`、第三方组件清单
- Maven 运行时/测试依赖清单、SBOM 和许可证清单
- `licenses/` 第三方许可文本与来源材料
- 应用运行所需的空 `logs/`、`temp/` 目录

应用包不包含：

- JDK/JRE
- sherpa-onnx Native Runtime
- ONNX Runtime
- SenseVoiceSmall 模型
- FFmpeg
- Microsoft Visual C++ Redistributable

## 7. 目标机三阶段验收

### 第一阶段：准备运行环境

1. 安装 Java 11 并执行 `java -version`。
2. 下载、解压并配置 sherpa-onnx Native Runtime。
3. 下载、解压并配置 SenseVoiceSmall INT8 模型。
4. 安装 FFmpeg 并执行 `ffmpeg -version`。
5. 逐项记录 SHA-256 与实际输出。

### 第二阶段：部署 OfflineASR

1. 获取应用包并校验 `checksums.sha256`。
2. 设置 `JAVA_HOME`、`ASR_SHERPA_NATIVE_PATH`、`ASR_MODEL_DIR`、`ASR_FFMPEG` 或对应 `PATH`。
3. 前台启动服务。
4. 访问 `GET http://127.0.0.1:8080/api/asr/health`。
5. 成功判定：`applicationStatus=READY`、`modelLoaded=true`、`ffmpegAvailable=true`。

### 第三阶段：真实验收

1. 用已授权音频调用 `POST /api/asr`，确认非空识别结果。
2. 在本机 Chrome 验证麦克风选择、录音和上传识别。
3. 断网后重启服务并重复真实音频识别。
4. 需要服务化运行时，先获得授权再安装服务，并重新完成上述验收。
