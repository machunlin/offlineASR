### 2.2 SenseVoiceSmall INT8 模型

- 官方模型卡：<https://huggingface.co/FunAudioLLM/SenseVoiceSmall>
- 原始模型来源：ModelScope `iic/SenseVoiceSmall`，模型卡/上游 sherpa-onnx 文档说明 INT8 ONNX 版本由 sherpa-onnx 导出。
- 上游模型许可：<https://github.com/modelscope/FunASR/blob/main/MODEL_LICENSE>
- 许可版本：FunASR Model Open Source License Agreement v1.1。
- 关键要求：使用、复制、修改或分享模型时，必须注明来源和作者信息，并保留相关模型名称（协议第 2.2 条）。
- 上游 SenseVoice README 的许可说明称，官方 SenseVoiceSmall 权重可在遵守模型协议的前提下商业使用；但其引用的许可讨论 Issue #334 仍显示等待许可方/核心维护者确认，早期评论明确声明不能代替最终许可方确认。因此本记录不把该 Issue 评论当作最终授权文件。
- 适用于官方模型权重的结论不能自动套用到第三方量化、转换、二次打包或镜像仓库；必须确认实际模型文件的来源和版本。

**交付要求：**

1. 固定实际模型下载地址、上游归档版本/Commit、文件大小和 SHA-256。
2. 保留原始模型卡、FunASR 模型许可文本及来源链接。
3. 在产品“关于/许可证”页面或随包声明中明确标注，例如：`SenseVoiceSmall by FunASR / FunAudioLLM`，并链接官方模型卡和模型协议。
4. 不得把模型权重标注为 MIT 或 Apache-2.0。
5. 正式商业交付前，针对“商业产品内置分发官方 SenseVoiceSmall INT8 转换权重”的场景，取得许可方/核心维护者确认或完成法律审核。

### 2.3 FFmpeg

- 官方许可说明：<https://www.ffmpeg.org/legal.html>
- 官方许可证文件：<https://github.com/FFmpeg/FFmpeg/blob/master/LICENSE.md>
- 默认许可证：LGPL-2.1-or-later；部分可选组件/优化使用 GPL-2.0-or-later，启用后会改变整个 FFmpeg 构建的许可属性。
- `--enable-nonfree` 可能使构建产物不可再分发。
- FFmpeg 官方合规说明强调应针对实际构建检查配置，并按适用许可证提供相应源码、修改差异和构建配置等材料。
- 当前项目的 Windows/Linux/macOS 文档只要求用户提供 FFmpeg 可执行文件；打包脚本创建目录但不下载、不固定版本，也不记录构建配置。因此当前不存在可据以完成许可证判断的确定 FFmpeg 二进制。

**交付要求：**

1. 选定具体来源、版本、架构和 SHA-256；不得只写“FFmpeg 最新版”。
2. 保存 `ffmpeg -version` 和 `ffmpeg -buildconf` 输出。
3. 核查 GPL、nonfree、version3 选项以及外部库（例如 x264/x265、fdk-aac 等）的启用情况。
4. 若再分发二进制，准备与二进制完全对应的源码、修改补丁、构建配置和许可证文本，并按适用许可证履行提供义务。
5. 不得默认采用 gyan.dev 的 Windows 静态构建作为商业包资产；其下载页说明其常见静态构建采用 GPLv3。除非项目明确接受 GPL 合规义务并完成审核，否则应选择经过验证的 LGPL-only 构建，或要求客户自行安装合规版本。
6. 若不能完成上述核验，部署包不包含 FFmpeg，由客户按其组织许可政策自行安装；文档必须明确这不是完整离线包。

### 2.4 Java 11 Runtime

- 当前项目只要求 Java 11，未在仓库中固定发行商、完整版本、构建号或下载地址。
- 当前打包脚本仅创建空的 `jdk/` 目录，不包含 JDK/JRE。
- Eclipse Temurin 官方 FAQ：<https://adoptium.net/docs/faq>，说明 Temurin 二进制采用 GNU GPL v2 with Classpath Exception。
- Temurin 发行包还包含第三方组件及其独立许可信息；应保留发行包中的 `legal/` 目录和相关许可文件，不能只复制 `bin/java` 和少量运行库文件。
- GPL Classpath Exception 的作用是允许 Java 运行时与独立应用模块组合，不意味着可以忽略 Temurin 自身的许可证、版权声明和再分发要求。

**交付要求：**

1. 明确选用 Temurin 或其他发行商，并固定完整版本、平台架构、下载 URL 和 SHA-256。
2. 从官方发行包原样提取 Runtime，不得从开发机拷贝不完整的 Java 目录。
3. 随包保留 `legal/`、许可证、第三方声明和其他发行商要求的文件。
4. 如果更换发行商，重新核验，不得沿用 Temurin 的结论。

**尚未完成的事项：**

- 当前仅确认 Spring Boot 主框架许可证，尚未逐项核验 Maven 解析后的所有传递依赖。
- `pom.xml` 中 sherpa-onnx JAR 使用 `system` scope，本地 JAR 不会像普通 Maven Central 依赖一样完整呈现在常规依赖解析报告中；必须单独纳入第三方组件清单。
- 发布前应在实际构建环境执行 `mvn dependency:tree`，导出运行时和测试依赖；区分 compile/runtime 与 test scope，并对每个构件的确切版本和许可证进行扫描、人工复核。
- 对许可证元数据缺失、多个许可证、特殊例外或来源不明的构件，不能自动按宽松许可证放行。

## 3. 当前仓库与打包流程的事实

根据本次检查的 `pom.xml`、部署手册和打包脚本：

- 项目自身根目录有 MIT License。
- sherpa-onnx 2.0.3 的 JVM/平台 JAR 已作为本地依赖存在或由脚本下载。
- Windows/Linux 打包脚本创建 `jdk/`、`models/`、`ffmpeg/` 目录，但不负责下载或复制完整模型、Java Runtime 和 FFmpeg。
- Windows 部署手册要求 Java Runtime、模型、FFmpeg 来源及再分发许可由发布人员核验。
- Linux 部署手册同样要求补齐经许可核验的 Java Runtime、模型和 FFmpeg。
- WinSW 配置文件被复制，但当前打包脚本未复制 WinSW 可执行文件。
- 因此当前生成的 Windows/Linux 目录是部署包骨架，不是已完成许可证核验的完整离线安装包。

## 4. 发布前必须归档的文件

每个正式版本至少应归档：

- `THIRD_PARTY_NOTICES.md`：组件名称、版本、来源、许可证和版权声明；
- `THIRD_PARTY_LICENSES/`：适用的许可证原文和 NOTICE；
- `DEPENDENCIES.txt`：Maven 运行时/测试依赖及版本；
- `SBOM.cdx.json`：建议使用 CycloneDX 格式记录软件物料清单；
- `SHA256SUMS.txt`：最终交付压缩包及关键资产哈希；
- FFmpeg 的版本、构建配置、源码及修改补丁获取方式；
- Java Runtime 的发行商、版本、原始发行包及 `legal/` 目录；
- SenseVoiceSmall 的模型卡、许可文本、来源版本和模型文件哈希；
- sherpa-onnx 各平台 Native JAR 的来源、版本、SHA-256 和内嵌第三方库清单。

## 5. 发布阻断条件

出现以下任一情况，暂停对应组件的再分发和正式发布：

1. 无法确认组件来源或准确版本；
2. 无法取得适用许可证文本；
3. 许可证不允许计划中的商业使用或再分发；
4. 必须提供的声明、源码、修改补丁或构建信息未准备；
5. 模型许可、实际模型来源或商业分发范围不明确；
6. FFmpeg 的实际构建选项和外部库无法确认；
7. JDK 发行商、版本或随包许可文件不明确；
8. Maven 传递依赖或 Native JAR 内嵌依赖尚未完成清点。

不得将“可下载”“开源项目”“公开 Release”或“上游仓库显示 Apache/MIT”直接等同于“当前打包文件可以不附条件地随商业产品再分发”。
