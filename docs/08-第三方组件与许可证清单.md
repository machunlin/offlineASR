# 第三方组件与许可证清单

本文用于客户交付前的许可证核验，不构成法律意见。项目采用 MIT License，但该许可不自动覆盖模型、JDK、FFmpeg、sherpa-onnx 或其他第三方组件。

## 1. 核验原则

- 以实际打包的文件、准确版本、构建选项和上游发布页面为准。
- 不能仅凭组件名称推断许可证；尤其要核对 FFmpeg 编译配置、模型权重许可和 JDK 发行商条款。
- 记录上游项目、下载地址、版本/Commit、许可证名称、许可证原文位置、是否允许再分发、是否需要附带声明或源码。
- 许可证文件应随交付包提供或在发布页提供可访问副本。
- 未完成核验的组件不得随客户交付包再分发；可改为由客户从官方渠道自行获取，但必须明确记录。

|---|---|---|---|---|

## 3. 每次发布必须归档的信息

建议为每个正式版本生成并归档：

- `THIRD_PARTY_NOTICES.md`：第三方组件、版本、来源、许可证和版权声明；
- `THIRD_PARTY_LICENSES/`：需要随包分发的许可证原文；
- `DEPENDENCIES.txt`：Maven 依赖及版本清单；
- `SHA256SUMS.txt`：最终交付压缩包及关键资产哈希；
- 模型和原生运行库的来源、版本、架构、构建参数记录。

## 4. 发布阻断条件

出现以下任一情况，暂停对应组件的再分发和正式发布：

1. 无法确认组件来源或准确版本；
2. 无法取得适用许可证文本；
3. 许可证不允许计划中的商业使用或再分发；
4. 必须提供的声明、源码或构建信息未准备；
5. 模型许可不明确或与客户使用场景冲突；
6. FFmpeg 的实际构建选项无法确认。

不得将“可下载”“开源项目”或“公开 Release”直接等同于“允许随商业产品再分发”。
