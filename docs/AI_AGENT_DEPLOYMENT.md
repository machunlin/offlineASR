# AI Agent 部署任务入口

本文是自动化部署的唯一入口。AI Agent 应先阅读本文，再按目标操作系统选择正式部署手册。

## 一句话任务指令

> 请阅读仓库中的 docs/AI_AGENT_DEPLOYMENT.md，识别当前目标机器的操作系统和 CPU 架构，按对应平台的正式部署手册检查并校验完整 OfflineASR 部署包，完成部署、启动、健康检查和一次真实音频识别验证，最后汇报执行命令、实际结果、日志位置及未通过项目。未经授权不要开放公网/局域网访问、修改防火墙、创建系统用户、安装系统服务或覆盖现有配置。

## 1. 固定原则

1. 先检查操作系统、CPU 架构、磁盘、内存和部署包版本。
2. 先确认部署目录及工作区状态，不覆盖用户文件。
3. 优先使用包含 Java 11 Runtime、模型和 FFmpeg 的完整离线包。
4. 执行平台校验脚本；SHA-256 失败或必需资产缺失时停止部署。
5. 不得把开发机上的 Maven、Python 或 IDE 当作客户机运行依赖。
6. 不得下载来源不明的模型、JDK、FFmpeg 或原生库。
7. 默认只监听 127.0.0.1:8080，不得擅自改为 0.0.0.0。
8. 健康检查成功不等于真实识别成功；必须执行真实音频识别。
9. 未经授权不得创建用户、安装系统服务、修改防火墙、端口或重启其他业务。
10. 报告不得包含客户语音文本、密码、密钥或其他敏感信息。

## 2. 平台选择

| 平台 | 正式手册 | 校验入口 |
|---|---|---|
| Windows 10/11 x64 | [Windows 部署手册](03-Windows部署手册.md) | scripts/windows-verify-package.ps1 |
| Ubuntu 22.04 x86_64 | [Linux 部署手册](04-Linux部署手册.md) | scripts/linux-verify-package.sh |
| macOS ARM64 | [macOS 运行指南](05-macOS运行指南.md) | 本机开发和验证，不属于当前客户离线发布包 |

不支持的 CPU 架构或操作系统应停止并报告，不得套用其他平台原生库。

## 3. 标准部署步骤

1. 检查部署包目录结构及版本。
2. Windows 执行 PowerShell 校验脚本；Linux 执行 shell 校验脚本。
3. 检查 Java 11 Runtime、模型文件、FFmpeg 和配置是否齐全。
4. 将部署包放入经客户确认的固定目录。
5. 前台启动服务，等待模型初始化完成。
6. 执行 GET /api/asr/health，确认 applicationStatus=READY、modelLoaded=true、ffmpegAvailable=true。
7. 使用已授权的测试音频调用 POST /api/asr，确认返回非空识别结果。
8. 在目标主机 Chrome 验证麦克风录音、设备选择和音频上传。
9. 如客户要求离线运行，断网重启并重复真实识别。
10. 如客户需要服务化运行，先提交安装计划并获得授权，再安装和验收。

## 4. 最终报告

每项标记为“通过 / 失败 / 未执行”，至少报告：
- 操作系统、CPU 架构和部署包版本；
- 部署目录及完整性校验结果；
- Java、模型、FFmpeg 检查结果；
- 服务启动与健康检查结果；
- 真实音频接口识别、Chrome 麦克风和上传识别结果；
- 断网、服务化验收结果；
- 日志位置和资源占用；
- 未完成事项及阻断原因。

不得推测测试结果，不得在报告中粘贴真实语音识别内容。
