# 版本发布与客户交付规范

## 1. 版本规则

- Maven `pom.xml` 的 `project.version` 是应用版本号唯一来源。
- 开发版本使用 `X.Y.Z-SNAPSHOT`；正式版本使用 `X.Y.Z`。
- Git 标签统一使用 `vX.Y.Z`，例如 Maven 版本 `0.1.0` 对应标签 `v0.1.0`。
- 正式版本标签必须指向已经通过三平台 CI、发布验收和许可核验的提交。
- 不允许在正式版本发布后修改同名标签或覆盖 Release 资产。

当前仓库版本为 `0.1.0-SNAPSHOT`。当前尚无 Git 标签和 GitHub Release；这表示尚未建立正式版本发布记录，不代表已有客户交付包。

## 2. 发布前置条件

以下条件必须全部满足，任何一项不满足都不得标记为正式发布：

1. 从最新 `develop` 拉取代码，检查工作区和待提交变更。
2. 明确本次版本范围、变更说明、已知问题和升级影响。
3. 将 `pom.xml` 版本从 SNAPSHOT 调整为正式版本，并同步检查启动日志、健康接口和部署说明中的版本展示。
4. macOS ARM64、Windows x64、Linux x64 CI 全部通过。
5. Windows/Linux 分别生成目标平台部署包；不能把 CI 的包结构检查当作客户机实机验收。
6. JDK、SenseVoiceSmall 模型、FFmpeg 和 sherpa-onnx 原生库均来自可信上游，版本、架构、来源和许可证已记录。
7. 完整部署包通过平台校验脚本，生成 SHA-256 清单并再次校验。
8. 至少完成本次目标平台的真实启动、健康检查和真实音频识别；未实测的平台必须在发布说明中明确标注。
9. 检查包内不含客户录音、日志、临时文件、密钥、个人配置和开发机路径。
10. 完成第三方组件许可证清单核验，确认项目许可证与第三方许可证的边界。

## 3. 标准发布流程

### 3.1 冻结版本

1. 确认 `develop` 工作区干净并拉取远端最新代码。
2. 更新 `pom.xml` 的正式版本号。
3. 更新本次发布说明，列出功能、修复、兼容性变化、限制和验收范围。
4. 提交版本变更并等待完整 CI 通过。

### 3.2 组装交付包

在对应平台准备完整离线运行资产，按平台部署手册执行打包。发布目录约定：

- Windows：`dist/windows-x64/`
- Linux：`dist/linux-x64/`

完整包至少包含应用 JAR、对应平台原生库、Java 11 Runtime、SenseVoiceSmall INT8 模型、FFmpeg、配置、启动/停止脚本、校验脚本和部署说明。

生成并验证 SHA-256 清单：

- Linux：`bash scripts/linux-generate-checksums.sh dist/linux-x64`，再执行 `bash scripts/linux-verify-package.sh dist/linux-x64`。
- Windows：在 PowerShell 中从部署包根目录执行 `powershell -ExecutionPolicy Bypass -File .\\scripts\\windows-generate-checksums.ps1 -Root .`，再执行 `powershell -ExecutionPolicy Bypass -File .\\scripts\\windows-verify-package.ps1 -Root .`。

校验失败、必需文件缺失或第三方许可未确认时停止发布。

### 3.3 命名和校验

正式交付文件命名统一为：

- `offline-asr-vX.Y.Z-windows-x64.zip`
- `offline-asr-vX.Y.Z-linux-x64.tar.gz`

压缩包旁提供 `SHA256SUMS.txt` 和本次发布说明。校验文件必须针对最终压缩文件计算，不得复用目录内部文件清单替代压缩包哈希。

### 3.4 GitHub Release

1. 创建并推送 `vX.Y.Z` 标签，标签指向已验收提交。
2. 以该标签创建 GitHub Release。
3. 填写版本变更、运行环境、部署步骤、已验证平台、未验证平台、已知限制和升级/回滚提示。
4. 上传最终 Windows/Linux 完整离线包、对应 SHA-256 文件及第三方许可清单。
5. 下载 Release 资产进行一次独立哈希校验，再将 Release 标记为正式发布。
6. 不把源码 ZIP 自动归类为完整离线部署包；源码归档与客户安装包必须明确区分。

正式 Release 和标签属于对外发布动作。未经项目负责人明确确认，不得创建、推送或覆盖。

## 4. 客户交付清单

每次交付至少提供：

- 对应平台的完整离线部署包；
- SHA-256 校验文件；
- 版本发布说明；
- 对应平台部署手册或 AI Agent 部署入口；
- 第三方组件及许可证清单；
- 实机验收记录（注明 OS、CPU、浏览器、Java、模型版本和识别测试结果）；
- 升级、回滚、卸载说明。

客户验收报告不得包含真实语音内容、账号密码、密钥或其他敏感数据。

## 5. 升级与回滚原则

- 升级前备份配置并记录当前版本、模型文件哈希和健康状态。
- 不覆盖客户配置、模型和日志；需要迁移时先说明差异并获得授权。
- 新旧版本目录分离，优先采用可回滚的目录切换方式。
- 升级后执行健康检查和真实音频识别；失败时恢复上一完整版本。
- 卸载默认保留客户配置、模型和日志，删除前必须获得现场负责人确认。

详细操作参见 [版本升级与卸载](06-版本升级与卸载.md)。
