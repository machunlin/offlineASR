# 版本发布与客户交付规范

## 1. 版本规则

- Maven `pom.xml` 的 `project.version` 是应用版本号唯一来源。
- 开发版本使用 `X.Y.Z-SNAPSHOT`；正式版本使用 `X.Y.Z`。
- Git 标签统一使用 `vX.Y.Z`，例如 Maven 版本 `0.1.0` 对应标签 `v0.1.0`。
- 正式版本标签必须指向已经通过三平台 CI、目标平台验收和许可核验的提交。
- 不允许在正式版本发布后修改同名标签或覆盖 Release 资产。

当前仓库版本为 `0.1.0-SNAPSHOT`。本次依赖交付模式调整不创建标签、Release 或正式客户离线包。

## 2. 交付边界

OfflineASR 只交付项目自身应用文件。以下外部运行依赖由客户或技术支持工程师自行下载、安装和配置：

1. Java 11 Runtime。
2. sherpa-onnx 2.0.3 Native JAR 中的 JNI 与 ONNX Runtime Native。
3. SenseVoiceSmall INT8 `2025-09-09` 模型。
4. FFmpeg。
5. 其他平台运行库，例如 Windows Microsoft Visual C++ Redistributable。

应用 Fat JAR 继续包含 `sherpa-onnx-jvm-2.0.3.jar` Java API/Wrapper，因为它不是 Native 二进制，而是应用调用 sherpa-onnx 的编译依赖。必须同时遵守：

- 不把 `sherpa-onnx-native-lib-*.jar` 加入 Maven 依赖。
- 不把 JNI、ONNX Runtime、模型、FFmpeg 或 JRE 复制到部署包。
- 不生成包含上述外部依赖的“完整离线交付包”。

## 3. 发布前置条件

以下条件必须全部满足，任何一项不满足都不得标记为正式发布：

1. 从最新 `develop` 拉取代码，检查工作区和待提交变更。
2. 明确版本范围、变更说明、已知问题和升级影响。
3. 将 `pom.xml` 版本从 SNAPSHOT 调整为正式版本。
4. macOS ARM64、Windows x64、Linux x64 CI 通过。
5. Fat JAR 包含 Java Wrapper，且不包含任何 `sherpa-onnx-native-lib-*.jar`、JNI 或 ONNX Runtime 文件。
6. Windows/Linux 分别生成只含应用文件的部署包，并通过平台静态校验。
7. 应用包不包含 `jdk/`、`ffmpeg/`、`models/`、`external/sherpa-onnx-native/`。
8. 部署包的 `checksums.sha256` 已生成、复验，且最终压缩包另有独立 SHA-256。
9. 至少完成目标平台真实启动、health、真实音频识别；其他平台标记“未验证”。
10. 第三方组件清单中的模型和 FFmpeg 许可风险有明确结论；未确认项不得写成已授权。

## 4. 标准发布流程

### 4.1 冻结版本

1. 确认 `develop` 工作区干净并拉取远端最新代码。
2. 更新 `pom.xml` 正式版本号。
3. 更新发布说明，列出功能、修复、兼容性变化、限制和验收范围。
4. 提交版本变更并等待完整 CI 通过。

### 4.2 组装应用包

Windows：

```powershell
.\scripts\windows-package.bat
```

Linux：

```bash
bash scripts/linux-package.sh
```

输出目录：

- Windows：`dist/windows-x64/`
- Linux：`dist/linux-x64/`

应用包至少包含：

- `app/offline-asr.jar`，其中含 Java Wrapper，不含 Native Runtime；
- `config/application.yml`；
- 启动、诊断、停止、服务安装/卸载和校验脚本；
- 项目 `LICENSE`、当前部署文档和第三方组件清单；
- Maven 运行时/测试依赖清单、CycloneDX SBOM、许可证清单和许可文本；
- 空 `logs/`、`temp/` 目录；
- `checksums.sha256`。

应用包不得包含：

- Java Runtime/JDK；
- `sherpa-onnx-native-lib-*.jar`；
- JNI、ONNX Runtime；
- SenseVoiceSmall 模型；
- FFmpeg；
- 客户录音、日志、临时文件、密钥或个人配置。

### 4.3 校验

Linux：

```bash
bash scripts/linux-generate-checksums.sh dist/linux-x64
bash scripts/linux-verify-package.sh dist/linux-x64
```

Windows：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\windows-generate-checksums.ps1 -Root .\dist\windows-x64
powershell -ExecutionPolicy Bypass -File .\scripts\windows-verify-package.ps1 -Root .\dist\windows-x64
```

校验失败、Fat JAR 出现 Native Runtime、必需文件缺失或许可阻断项未处理时停止发布。

### 4.4 命名和压缩包校验

建议命名：

- `offline-asr-vX.Y.Z-windows-x64.zip`
- `offline-asr-vX.Y.Z-linux-x64.tar.gz`

压缩包旁提供 `SHA256SUMS.txt` 和本次发布说明。校验必须针对最终压缩文件计算，不得用目录内 `checksums.sha256` 替代压缩包哈希。

## 5. 客户交付清单

每次交付至少提供：

- 对应平台应用包；
- 应用包 SHA-256 清单；
- 最终压缩包 SHA-256；
- 版本发布说明；
- 对应平台部署手册或 AI Agent 部署入口；
- 第三方组件与许可证清单、CycloneDX SBOM、Maven 依赖/许可证清单；
- 目标机 Java 11 版本与路径记录；
- 外部 Native、模型和 FFmpeg 的下载来源、版本和 SHA-256 核验记录；
- 实机验收记录，注明 OS、CPU、浏览器、Java、模型版本和结果；
- 升级、回滚、卸载说明。

## 6. 升级与回滚原则

- 升级前备份配置，记录当前应用版本、外部依赖位置和 health 状态。
- 应用包升级不覆盖客户配置、模型、Native Runtime、FFmpeg 或日志。
- 新旧应用目录分离，采用可回滚的目录切换方式。
- 升级后执行 human-readable health 检查和真实音频识别；失败时恢复上一应用目录。
- 卸载默认保留客户配置、模型、Native Runtime、FFmpeg 和日志；删除前取得现场负责人确认。

详细操作参见 [版本升级与卸载](06-版本升级与卸载.md)。

正式 Release、Tag 和对外发布动作必须经项目负责人明确确认。
