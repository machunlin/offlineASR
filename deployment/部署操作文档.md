### 3.4 将 Maven 产物替换为 Linux x64 专用 JAR

`develop` 默认构建会打入 macOS ARM64 原生 JAR，不能直接用于 Linux。部署时执行以下替换，不修改 GitHub 源码，也不提交代码：

1. 解包 Maven 生成的 Spring Boot JAR。
2. 删除：
   ```text
   BOOT-INF/lib/sherpa-onnx-native-lib-osx-aarch64-2.0.3.jar
   ```
3. 加入：
   ```text
   BOOT-INF/lib/sherpa-onnx-native-lib-linux-x64-2.0.3.jar
   ```
4. 更新 `BOOT-INF/classpath.idx` 中对应的原生库条目。
5. 重新封装可执行 JAR。

关键要求：Spring Boot 嵌套 JAR 必须使用 `Stored`，不能压缩。首次封装的错误方式是普通 `zip -r`，服务启动时报：

```text
Unable to open nested entry ... It has been compressed and nested jar files must be stored without compression
```

正确封装必须使用：

```bash
zip -0 -q -r ../offline-asr-linux-x64.jar .
```

发布前检查：

```bash
unzip -t app.jar
unzip -p app.jar BOOT-INF/classpath.idx | grep sherpa-onnx-native-lib
unzip -l app.jar | grep -E 'sherpa-onnx-native-lib|\.dylib|\.dll'
```

验收标准：

- 只包含 Linux x64 原生 JAR；
- 不包含 `.dylib`、`.dll`、`osx-aarch64` 或 `win-x64`；
- 所有 `BOOT-INF/lib/*.jar` 的压缩方式为 `Stored`。

## 6. systemd 服务配置

创建 `/etc/systemd/system/offline-asr.service`：

```ini
[Unit]
Description=Offline ASR Service
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=ubuntu
Group=ubuntu
WorkingDirectory=/home/ubuntu/offline-asr
Environment=JAVA_HOME=/usr/lib/jvm/java-11-openjdk-amd64
Environment=PATH=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin
Environment=ASR_HOST=0.0.0.0
Environment=ASR_PORT=8080
Environment=ASR_MODEL_DIR=/home/ubuntu/offline-asr/models/SenseVoiceSmall
Environment=ASR_TEMP_DIR=/home/ubuntu/offline-asr/temp
Environment=ASR_FFMPEG=/usr/bin/ffmpeg
Environment=ASR_THREADS=2
Environment=ASR_MAX_UPLOAD_MB=50
Environment=ASR_MAX_DURATION_SECONDS=600
Environment=ASR_DECODE_TIMEOUT_SECONDS=60
Environment=ASR_QUEUE_TIMEOUT_SECONDS=5
Environment=ASR_TEMP_RETENTION_HOURS=4
ExecStart=/usr/bin/java -Xms128m -Xmx640m -XX:MaxMetaspaceSize=160m -jar /home/ubuntu/offline-asr/app/offline-asr.jar
SuccessExitStatus=143
Restart=on-failure
RestartSec=5
TimeoutStopSec=20
KillSignal=SIGTERM
UMask=0027
NoNewPrivileges=true
ProtectSystem=full
ProtectKernelTunables=true
ProtectKernelModules=true
ProtectControlGroups=true
RestrictSUIDSGID=true
LockPersonality=true
RestrictAddressFamilies=AF_UNIX AF_INET AF_INET6
StandardOutput=append:/home/ubuntu/offline-asr/logs/stdout.log
StandardError=append:/home/ubuntu/offline-asr/logs/stderr.log

[Install]
WantedBy=multi-user.target
```

启用并启动：

```bash
sudo systemctl daemon-reload
sudo systemctl enable offline-asr
sudo systemctl restart offline-asr
```

## 7. 监听地址检查

仓库 `src/main/resources/application.yml` 默认值为：

```yaml
server:
  address: ${ASR_HOST:127.0.0.1}
  port: ${ASR_PORT:8080}
```

默认仅监听本机，安全上不应直接改成 `0.0.0.0`。当前 Linux 部署通过 systemd 覆盖：

```text
ASR_HOST=0.0.0.0
ASR_PORT=8080
```

实际进程环境、监听端口和连通性均已核验：

```text
ASR_HOST=0.0.0.0
LISTEN *:8080
eth0_http=200
tailscale_http=200
```

因此当前 Linux 服务配置正确；公网不可达不再是 Java 监听地址问题。

## 10. 网络与 HTTPS

### 公网 HTTP

公网访问：

```text
http://124.221.243.130:8080/index.html
```

当前从本机访问连接超时。服务器内部检查结论：

- Java 正常监听 `*:8080`；
- UFW 未启用；
- 主机 INPUT 策略为 `ACCEPT`，未发现针对 8080 的阻断；
- 内网和 Tailscale 地址访问均返回 200。

剩余阻塞项为腾讯云安全组未放行 TCP 8080，正在由用户核查。

### 公网 HTTPS

当前没有绑定域名和公网 TLS 证书，因此不能直接把现有 HTTP 地址转换为浏览器信任的公网 HTTPS。

可选方案：

1. 绑定域名并申请受信任证书，在 8080 前增加 Nginx/Caddy TLS 反向代理。
2. 使用 Tailscale Serve 在同一 tailnet 内提供可信 HTTPS：
   ```bash
   sudo tailscale serve --bg --https=443 http://127.0.0.1:8080
   ```
   服务器 Tailscale 名称为：
   ```text
   vm-0-8-ubuntu.taild8a90c.ts.net
   ```
   该方案尚未启用，且要求访问浏览器处于同一 tailnet。
3. 临时公网 HTTPS 可使用受管理的隧道服务，但不适合作为长期生产入口，且会改变服务暴露边界。

不能通过关闭 Chrome 安全策略作为正式麦克风解决方案。
